## Goals

In this module, you'll run the app, ask Copilot to assess it, review the upgrade
plan, and check that the app still works after the upgrade. Use the
todo application in your own workshop repository (`LAB_APP_REPO`).

Here, you review and approve the plan before Copilot makes changes. In the next
module, the automated workflow makes changes first, and you review the pull request.

## 1. Get and run the app

From your repository's default branch, download the todo app using the setup
script from [module 00]({{ site.baseurl }}{% link appmod-lab/0-prerequisites/prerequisite-0-1-technical.md %}):

```powershell
Set-Location -LiteralPath $env:LAB_APP_REPO
& $env:LAB_SETUP -Module todo
git status --short
```

Review the downloaded `src` folder, then commit it to your default branch and push
it to your repository. This gives both the interactive and automated exercises
the same starting point:

```powershell
git add -- src
git commit -m "Add todo application for workshop"
git push
```

The `src/pom.xml` file
uses Java 8 and Spring Boot 2.7.18.
The app is a todo list with web pages generated by the server and a built-in H2 database.

First, check that the app builds and its tests pass before changing anything.
Set the path to your JDK 8 installation, then run:

```powershell
Set-Location -LiteralPath $env:LAB_APP_REPO
$env:JAVA_HOME = Read-Host 'Full path to your JDK 8 home directory'
if (-not (Test-Path (Join-Path $env:JAVA_HOME 'bin\java.exe')) -and $IsWindows) {
    throw 'The JDK 8 directory does not contain bin\java.exe.'
}
$env:PATH = (Join-Path $env:JAVA_HOME 'bin') + [IO.Path]::PathSeparator + $env:PATH
java -version
mvn --version
mvn --file (Join-Path $env:LAB_APP_REPO 'src\pom.xml') --batch-mode --no-transfer-progress verify
if ($LASTEXITCODE -ne 0) { throw 'The build or tests failed. Fix the issue before upgrading.' }
```

Check that Maven shows Java 8 and the command passes. If something fails, note the
error and investigate it before upgrading so you know it wasn't caused by the upgrade.

Run the application on a free local port:

```powershell
$todoPort = Read-Host 'Free local port for the todo application'
mvn --file (Join-Path $env:LAB_APP_REPO 'src\pom.xml') spring-boot:run "-Dspring-boot.run.arguments=--server.port=$todoPort"
```

Open `http://127.0.0.1:<your-port>` in a browser. Create a todo, mark it complete,
and delete it. Stop the app with Ctrl+C. Use sample data only, not customer data.

## 2. Create a branch for the upgrade

Check for uncommitted changes with `git status --short`. Save any existing work
before continuing, then create a branch for the upgrade:

```powershell
git status --short
$upgradeBranch = Read-Host 'New branch name for the interactive upgrade'
git switch -c $upgradeBranch
if ($LASTEXITCODE -ne 0) { throw 'Could not create the upgrade branch.' }
```

Leave your repository's default branch unchanged. The automated workflow in the next
module uses that branch, not the upgrade branch you just created.

## 3. Run an assessment and review the plan

Open your workshop repository (`LAB_APP_REPO`) in Visual Studio Code and sign in
to GitHub Copilot. Select **GitHub Copilot modernization** in the activity bar.

[![VS Code activity bar with the GitHub Copilot modernization icon outlined in red and an arrow pointing to it.]({{ '/assets/images/GitHub_Copilot_modernization_extension.png' | relative_url }})]({{ '/assets/images/GitHub_Copilot_modernization_extension.png' | relative_url }})

**What this shows:** The red box and arrow mark the icon that opens the
modernization panel. The screenshot uses PetClinic; keep your todo repository
open for this module. Select a screenshot to view it full size.

In the **Quickstart** panel, select **Start Assessment**.

[![Modernization Quickstart panel with Start Assessment above the runtime upgrade, Azure migration, and security actions.]({{ '/assets/images/quickstart.png' | relative_url }})]({{ '/assets/images/quickstart.png' | relative_url }})

**What this shows:** Assessment is the starting point. The other buttons start
specific upgrade, migration, or security work; you do not need to run them all.
Labels can differ between extension versions.

After reviewing the assessment output, select **Upgrade Java Runtime &
Frameworks**. Choose a supported Java version and a compatible framework version
if needed. Agree on these with the customer. The newest version may not be the
right choice for the app.

Ask Copilot to create a plan before making changes. Review what it will change,
what should keep working, how to test it, any security issues, and how to undo
the upgrade.

You can use this prompt and add the versions you've agreed on:

```text
Run an assessment on the todo app in src for an upgrade to [Java version]
and [framework version]. Keep the existing todo features working. Show me
what needs to change, what might break, which JDKs I need, how to test the
upgrade, and how to undo it. Wait for my approval before making changes.
```

Once you're happy with the plan, approve only the changes you've agreed on and
let Copilot run the upgrade. Follow the
[interactive modernization quickstart](https://learn.microsoft.com/azure/developer/github-copilot-app-modernization/quickstart-upgrade)
if the options in the extension look different.

## 4. Check the changes and test the app

When Copilot finishes, read its summary and check the files it changed:

```powershell
git status --short
git --no-pager diff
```

If Copilot created commits, compare them with your repository's default branch too.
Switch your terminal to the JDK you upgraded to, then rerun the Maven verification
command from step 1. Run the app again and check that you can still create,
complete, and delete a todo.

Note the versions used, commands run, results, and anything that still needs
checking or fixing. Don't merge the branch during this exercise. A passing build
or Copilot's summary alone doesn't mean the change is ready to release.

## Checkpoint

You should be able to explain what Copilot found, which plan you approved, what
changed, and whether the app still works. If the upgrade didn't finish, note what
blocked it and keep the error messages for follow-up.
